# WELLAR AI V2 — Phase 3C Dataset Qualification

**Recommendation: B — no verified, accessible, rights-cleared public media dataset currently qualifies as training data for Wellar's proposed pre-work occupational-fatigue target.** A few datasets are conditional research leads for separate drowsiness or mental-fatigue constructs. No sample was downloaded or processed in this phase.

## V2 extractor compatibility and sample processing

Inspected `app/media/extractors.py`, `app/media/contracts.py`, and `app/media/isolated_decode.py`.

- V2's video path decodes the whole bounded video with OpenCV and samples frames for MediaPipe FaceMesh. It emits descriptive eye/mouth geometry, coarse face-orientation proxies, luminance/blur, face/sampling coverage, missingness and quality status. It explicitly does not compute validated PERCLOS or fatigue/sleepiness predictions.
- The image path emits MediaPipe face visibility, eye/mouth ratios, brightness, blur and quality rejection. The audio path accepts uncompressed PCM WAV and emits signal-integrity summaries (RMS/peak, silence, clipping, DC offset); it does not extract speech, prosody, or voice-fatigue features.
- UL-DD's provided 68-point Dlib facial landmarks, 33-point pose landmarks, and action-unit feature tables are not V2's feature contract. Using those tables would require a reviewed mapping/adaptor. Raw RGB MP4 might be decodable, but its FaceMesh yield is unverified; IR and depth compatibility are especially unknown.
- DROZY's NIR MP4s are not a validated input mode for the current RGB FaceMesh extractor. UTA-RLDD is RGB video but no lawful sample was available for a compatibility test.
- **No extractor was run.** UL-DD files are access-controlled, DROZY is restricted against commercial-product development, and the other candidates lack verified usage rights or public data access. Thus extractor feature coverage, missingness, quality rejection and decoder compatibility are **not measured**; there is no sample-based pass/fail count. No facial template or media copy was created.

## Recommendation and exact pilot data after approvals

The first Wellar media-based fatigue experiment should use an approved, target-population pilot rather than treating driver-drowsiness labels as occupational fatigue. The existing Phase 2.1 decision proposes the continuous **OFER-15 Intershift Recovery (IR)** score as a pre-shift operationalization, but explicitly leaves its equivalence to residual pre-work fatigue unapproved. Do not reverse the native score or discretize it without expert review.

After written scientific, instrument-rights, ethics, privacy, site and consent approvals, each repeated pre-shift session should collect:

1. The authorized Arabic OFER-15 IR version and score using its native wording, scoring and timing, immediately before the work period; preserve item/scale timestamps. The independent occupational-fatigue researcher and Arabic psychometrician must first approve its construct and time-window fit.
2. KSS separately for momentary sleepiness and a validated PVT separately for vigilance, with fixed order/timing and raw trial timestamps. Disagreement is construct information, not dishonesty.
3. Only separately consented, synchronized image/video/audio modalities needed for the study, with technical metadata, device/site codes, quality and explicit missingness. Avoid identity templates; process locally under a reviewed retention/deletion plan.
4. Repeated sessions per participant across workdays, with the sample-size/precision plan set by an independent statistician. Keep all sessions from each participant in one split; reserve a custodian-held participant-disjoint test set and report participant-clustered uncertainty, coverage, abstention and modality-specific missingness.

## Scientific track and disposition

The existing Phase 2.1 decision and Phase 3A review package were not modified. The concrete next expert decision is written sign-off from an independent occupational-fatigue researcher and Arabic psychometrician on whether **OFER-15 IR's recovery construct, Arabic version, scoring and pre-shift timing are valid for office/customer-service employees**, or whether the target/instrument must change. The OFER rights holder must separately confirm use of the exact Arabic instrument, scoring, study app and commercial research. UL-DD's data custodian must separately grant restricted access and confirm permitted derivative-feature handling before any UL-DD sample is processed.

**Phase 3C recommendation: B.** No currently verified, legally accessible public media sample simultaneously satisfies the proposed occupational target, independent reference, usage rights and V2 compatibility criteria. Track B approval and real-employee enrollment remain blocked. No training, production inference, Docker activity or changes to Flutter/legacy/Directus/EasyPanel were performed. No tests were run because no implementation was changed and no lawful media sample was available.
